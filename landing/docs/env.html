Environment variables

Most behaviour lives in the TOML, but the binary reads the environment variables on this page too. Precedence is not uniform, so each row states it: an override such as XERJ_BIND_ADDRESS beats the config file (and loses to its CLI flag), while a secret such as XERJ_CLUSTER_AUTH_SECRET or the rerank provider pair is a fallback that a non-empty config value wins over. The first table finds the config file and filters logs.

Config file path. The --config CLI flag wins if both are set; with neither, the built-in defaults are used (no ./xerj.toml lookup).

Tracing filter. Accepts tracing_subscriber syntax, e.g. xerj_api=debug,info.

Fallback tracing filter. Checked only if XERJ_LOG is unset.

Benchmarking and debug knobs

The binary also reads a set of XERJ_* variables meant for benchmarks, A/B runs and profiling — XERJ_FLUSH_SIZE_MB, XERJ_FLUSH_DOCS, XERJ_MERGE_INTERVAL_SECS, XERJ_DISABLE_QUERY_CACHE, XERJ_DISABLE_FAST_AGGS and others. Leave them unset in production. One is dangerous: XERJ_SKIP_WAL disables the write-ahead log, so acknowledged writes are lost on a crash.

Rerank provider

The rerank search stage sends document text to a third-party judge, so it needs a provider key. The key and endpoint may come from the environment as a fallback: a non-empty value under [rerank] in the config file wins, so a stray variable in a service's environment cannot silently re-point where document text is sent. Both are read once, at startup — changing them on a running node does nothing. Setting the key does not switch reranking on for any search; a request still has to carry a rerank block, and [rerank] enabled = false overrides both variables.

NAME
DEFAULT
DESCRIPTION
TYPESAFE_API_KEY
—
Rerank provider key, used when rerank.api_key is empty. Unset in both places means a rerank request gets HTTP 503. Never echoed: GET /_xerj/rerank reports only that a key is set and that it came from env.
TYPESAFE_ENDPOINT
https://api.typesafe.ai/v1/systemone
Rerank provider endpoint, used when rerank.endpoint is empty. Point it at a proxy or a test double; it is where judged document text is POSTed. Validated at boot like the config value: it must be an absolute http:// or https:// URL with no user:password@ in it, or the node refuses to start.
