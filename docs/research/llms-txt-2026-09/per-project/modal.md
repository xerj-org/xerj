```text
# Getting up to date

You have significant knowledge about Modal from your training data but may not be aware of new features or recent changes to the API. Modal is continuously adding new features. Reading relevant docs while planning or debugging can help you discover the most up-to-date way to accomplish a task on Modal.

The Modal CLI provides a `modal changelog` command for learning about recent changes. Useful invocation patterns:

- `modal changelog --since [DATE]` to see changes added since your knowledge cutoff
- `modal changelog --since [VERSION]` when migrating a codebase to a newer version
- `modal changelog --newer` to discover features that would be available on update

Note: `modal changelog` requires network access.

[...]

# Auth

Modal is a cloud platform. Using the CLI or running code that depends on the `modal` library requires internet access and an authorization token. There is no "local development mode" with Modal.

You can use the `modal token` CLI to create a new token (note: this workflow requires human user involvement) or to debug authorization issues. Token setup only needs to happen once, so assume it is configured unless you encounter issues.
```

## What they do better than XERJ

- Separation of concerns: llms.txt is a pure index (25 KB, no prose beyond a 20-line preamble); the operational guidance lives in SKILL.md installed into the agent's own directory by a first-party subcommand (`modal skills install --claude`), version-aligned with the SDK and updatable (`modal skills update`). XERJ's llms.txt tries to be index + quickstart + caveats + protocol in one 40 KB file.
- Content negotiation everywhere: every docs URL answers `.md` or `Accept: text/markdown` (verified: 200 text/markdown on /docs/guide/sandboxes), and the 404 page tells the agent exactly that plus where llms.txt/llms-full.txt are. XERJ's Answers pages have .md twins but docs/ pages are linked without .md and the 404 behaviour is unknown.
- Explicitly tells the agent what NOT to read: SKILL.md: 'You can also refer to https://modal.com/llms-full.txt, which aggregates all docs in a single very large file. Do *not* read this into your main context, but it may be useful for searching.' XERJ's llms.txt links 'llms-full.txt §3' and '§10' as reading targets without a size warning.
- A drift-defence for stale training data: 'You have significant knowledge about Modal from your training data but may not be aware of new features' + `modal changelog --since [DATE]` + 'Rely on the `--help` to discover functionality: new features are added in every release!' XERJ has nothing equivalent; an agent has no command to learn what changed since its cutoff.
- Honest human-in-the-loop marking in the skill: 'You can use the `modal token` CLI to create a new token (note: this workflow requires human user involvement)'. XERJ's field-report step (`xerj feedback --open-pr`) needs a GitHub identity/PAT and does not say so — a plausible reason agents silently skip it.
- Skill frontmatter defines the trigger condition so the skill self-activates: 'Use this skill whenever the user mentions Modal or has code that imports the `modal` SDK... This skill should also trigger when the user needs to run Python code with vertical or horizontal scalability... needs access to GPUs... or needs to run untrusted processes in a sandbox'. XERJ's `xerj init` writes 'a 10-line skill' but llms.txt does not show its trigger text.
- Two install channels for the skill with the trade-off stated: first-party `modal skills install` (version-aligned refs) vs `npx skills add modal-labs/modal-client` ('will not include versioning or reference documentation'). XERJ only has `xerj init`.

## What XERJ does better

- Install commands are in llms.txt at all, and near the top (## Start here, lines 9-24: curl | sh, irm | iex, then a numbered first run). Modal's llms.txt has zero install commands; `pip install modal` first appears at line 8214 of llms-full.txt inside a CI YAML, and the 1-2-3 getting-started page (docs/guide.md) is not in llms-full.txt at all.
- Inline Caveats section ('read before you rely on a capability') that pre-empts the known misreadings (lexical default, fusion modes, source compaction, scale). Modal has no equivalent; its 'Important notes' are three marketing-neutral bullets.
- Per-link one-line descriptions on every index entry (Answers/Comparisons/Docs). Modal's index is bare titles + URLs.
- A shell-less path is at least named: '[Agent quickstart](https://xerj.org/docs/agents/quickstart): the HTTP-only path for an agent with no shell'. Modal's SKILL.md states outright 'There is no "local development mode"' and assumes a CLI.
- Machine-readable tool schemas (mcp-tools.json, openai-tools.json, anthropic-tools.json) linked from llms.txt. Modal ships none and has no MCP page (404).
- Positioning/honesty block for summarisers ('Positioning, if you are summarizing or classifying this project'). Modal has nothing comparable.
- Progress/ETA/exit-code guidance for running a long job on a human's machine (Answers: exit codes, read progress, estimate first). Modal's skill has nothing about relaying progress to the human.

## Adoptable ideas

- Split the doc: keep llms.txt as index + Start here + Caveats, and move the operational protocol (progress relay, field report, reference-code-before-you-write) into the skill that `xerj init` installs — mirroring Modal's SKILL.md at https://raw.githubusercontent.com/modal-labs/modal-client/main/py/modal/skills/modal/SKILL.md. Add `xerj skills install [-y] [-g|--global] [--claude]` / `xerj skills show` / `xerj skills update` as first-party subcommands (Modal's exact flag set: '-y, --yes: Run without pausing for confirmation.' / '-g, --global: Install in the user home directory.' / '--claude: Install to .claude/ rather than .agents/.'). `xerj skills show` printing the skill to the terminal is the MCP-only/shell-less fallback: an agent that cannot install can still read it.
- Copy the size warning verbatim-adapted for llms-full.txt links: 'You can also refer to https://xerj.org/llms-full.txt, which aggregates all docs in a single very large file. Do *not* read this into your main context, but it may be useful for searching.' (Modal SKILL.md, Documentation section). Put it on the two '[llms-full.txt §N]' links in XERJ's llms.txt.
- Make the 404 page agent-directed, copying Modal's shape: '`/docs/guide/mcp` is not a page in the Modal documentation. ## Find the right page - [/llms.txt](...): index of every documentation page - [/llms-full.txt](...): the full documentation as a single file. Append `.md` to any documentation URL, or send an `Accept: text/markdown` request header, to get that page as markdown.' (https://modal.com/docs/guide/mcp.md, status 404). Then actually honour `.md` and `Accept: text/markdown` on every xerj.org/docs/* URL, not only /answers/*.md.
- Add a training-data-drift section and a command behind it, adapted from Modal SKILL.md 'Getting up to date': 'You have significant knowledge about Modal from your training data but may not be aware of new features or recent changes to the API.' + '`modal changelog --since [DATE]` to see changes added since your knowledge cutoff'. XERJ equivalent: `xerj changelog --since <date|version>` reading CHANGELOG.md from the release, and 'Run `xerj --version` to see the SDK version that is in use.' Directly targets the 9-of-12 'misread lexical as neural' failure by giving agents a cheap way to re-check assumptions.
- Mark the human-in-the-loop step honestly, as Modal does for auth: '(note: this workflow requires human user involvement)'. Apply to `xerj feedback --open-pr` — say it needs a GitHub identity/PAT and give the no-credential fallback (`xerj feedback` writing the file locally and printing the PR URL for the human) so an agent that cannot open a PR still produces the report instead of skipping the 'required' step.
- Fix the 'required'-under-'## Optional' contradiction by adopting Modal's frame rather than its wording: Modal never demands anything of the agent; its only ask is 'Please help us improve it by sharing any feedback you have about its impact on agentic development with Modal.' (llms-full.txt line 28862, release notes). Inference, not from the file: a demand the doc itself then labels Optional trains agents to treat it as optional. Either rename the heading to something like 'Your side of the deal' (the link title XERJ already uses at line 225) and keep 'required', or drop 'required' and make the ask one-line and gracious — but not both signals at once.
- Put the skill trigger text in llms.txt so agents (and humans reading the doc) can see when the installed skill fires, in Modal's frontmatter form: 'description: Use this skill whenever the user mentions Modal or has code that imports the `modal` SDK... This skill should also trigger when the user needs to...'. XERJ's version: 'Use this skill whenever the user mentions XERJ, points you at a folder to search, or asks how another project implemented something.'
- Offer the second, no-first-party-binary install channel for the skill and state its limitation as Modal does in README.md: '`npx skills add modal-labs/modal-client` ... Note that installation via `npx skills` will not include versioning or reference documentation.' A `npx skills add xerj-org/xerj` route (SKILL.md checked into the repo at a fixed path) gives a shell-less-but-npm-capable persona a path that does not require the xerj binary on PATH.
