### plugin-hints.md ('Recommend your plugin from your CLI') — HTTP 200

<https://code.claude.com/docs/en/plugin-hints.md>

The distribution protocol third-party CLIs use: emit a one-line <claude-code-hint /> tag to stderr when $CLAUDECODE is set and Claude Code shows the user a one-time 'install this plugin?' prompt. Directly relevant to how a CLI like xerj could drive adoption from inside agent sessions.

```text
If you maintain a CLI or SDK and have a plugin in the official Anthropic marketplace, your tool can prompt Claude Code users to install that plugin. Your CLI writes a one-line marker to stderr when it detects it is running inside Claude Code. Claude Code reads the marker, strips it from the output, and shows the user a one-time install prompt.
[...]
  if [ -n "$CLAUDECODE" ]; then
    printf '%s\n' '<claude-code-hint v="1" type="plugin" value="example-cli@claude-plugins-official" />' >&2
  fi
[...]
| `--help` output           | Claude often runs help when exploring an unfamiliar CLI    |
| Unknown-subcommand errors | Reaches the moment Claude is confused about your interface |
| Login or auth success     | The user is already in a setup mindset                     |
| First-run welcome message | A natural onboarding moment                                |
[...]
* **Official marketplace**: the `value` must reference a plugin in an Anthropic-controlled marketplace such as `claude-plugins-official`. Hints that point to other marketplaces are silently dropped.
```

## What they do better than XERJ

- Every leaf .md page carries a 3-line banner linking back to llms.txt ('Fetch the complete documentation index at: ... Use this file to discover all available pages before exploring further'), so discovery works from any entry point, not only the hub.
- Install step ends with a verify command and the exact expected output ('prints a version number followed by `(Claude Code)`'), plus error-string-to-fix routing and shell-disambiguation text (PowerShell vs CMD).
- Install has multiple channels stated as equals (native curl/irm, Homebrew, WinGet, apt/dnf/apk, npm) with the trade-off of each (auto-update or not) in one sentence.
- A documented, gated protocol (plugin-hints.md) for a CLI to advertise its own integration from inside an agent session, with the touchpoints ranked by when the agent is paying attention.
- Consistent one-sentence descriptions on all 208 links, with an explicit recursive-index instruction; no headings that contradict the body.
- llms.txt is small enough (47 KB) to be read whole in one fetch and is structured by audience (Getting started / Build / Administration / Configuration / Reference / SDK).

## What XERJ does better

- XERJ's llms.txt is an actual agent brief: install commands, the PATH consequence, the verification note, the MCP `xerj init` step, and a query command are inline in 'Start here'. Claude Code's llms.txt contains zero commands — it is a plain auto-generated docs index and an agent must fetch quickstart.md to get any install line.
- XERJ has an inline Caveats block ('The DEFAULT embedding mode is lexical, not neural', `_source` size warning, RAM data point) that pre-empts known agent misreads; Claude Code's index has no honesty/caveat layer at all.
- XERJ has an explicit feedback/contribution ask with a one-command path (`xerj feedback --open-pr ...`) and an agent contribution protocol; Claude Code's agent-facing files have no feedback CTA (only a human 'Getting help' Discord line in quickstart.md).
- XERJ names the shell-less HTTP-only path and the CLI-only exception (`xerj autoindex`) explicitly; Claude Code's docs assume a terminal throughout the quickstart.
- XERJ's llms-full.txt (84 KB, 1,235 lines) is readable in one fetch; Claude Code's llms-full.txt is 9.5 MB / 98,912 lines with install at ~37% depth, and the root /llms-full.txt URL silently serves the HTML marketing page.
- XERJ ships tool schemas (mcp-tools.json, anthropic-tools.json) linked from llms.txt; Claude Code links no machine-readable tool schema.

## Adoptable ideas

- Per-page back-link banner. Every code.claude.com .md page starts with the same 3 lines: '> ## Documentation Index / > Fetch the complete documentation index at: https://code.claude.com/docs/llms.txt / > Use this file to discover all available pages before exploring further.' XERJ's /answers/*.md, /compare/*.md and /docs/* pages could carry the same banner pointing at https://xerj.org/llms.txt so an agent that lands on any leaf page finds the hub (and the install + field-report steps) in one hop.
- Verify step with the exact expected output, immediately after install (quickstart.md): 'To confirm the installation worked, run: claude --version / The command prints a version number followed by `(Claude Code)`.' XERJ's Start-here step could state the literal string `xerj --version` prints, so a shell-less or policy-constrained agent can report success/failure precisely.
- Error-string-to-fix routing in the install step (quickstart.md): 'If the install command fails with `syntax error near unexpected token '<'`, a `403`, or another curl error, see [Troubleshoot installation](/docs/en/troubleshoot-install#find-your-error) to match the error to a fix and for alternative install methods.' XERJ already has the PATH/command-not-found note; adding a dedicated 'find your error' anchor (https://xerj.org/docs/install#find-your-error style) with verbatim error strings would let agents self-route instead of filing nothing.
- Interface-neutral pointer at the top of the quickstart: '<Note> This guide covers the terminal CLI. Claude Code is also available on the [web]..., as a [desktop app]..., in [VS Code]... See [all interfaces]...' XERJ's llms.txt buries the no-shell path at line 31 ('Agent quickstart ... the HTTP-only path for an agent with no shell'); lifting a one-line 'No shell? Use the HTTP-only path: https://xerj.org/docs/agents/quickstart' into the first 10 lines addresses the shell-less-persona failure directly.
- Recursive index instruction phrasing (llms.txt line ~347): '> The links below point to documentation indexes. Follow each `/_llms/` index recursively until you reach documentation pages.' XERJ's llms.txt could add a similar one-line blockquote before its Docs/Answers sections telling agents that the .md links are complete pages and the hub is authoritative.
- Split CLI vs MCP install into the two canonical one-liners the way mcp.md does: 'claude mcp add --transport http <name> <url>' and the `.mcp.json` block converted with 'claude mcp add-json example '{"command":"npx","args":["-y","@example/mcp-server"]}''. XERJ's llms.txt mentions `xerj init` writes .mcp.json (line 22) but shows no verbatim .mcp.json / `claude mcp add` snippet; adding the literal `claude mcp add xerj -- xerj mcp` (or whatever the real command is) plus the JSON would give MCP-only personas a copy-paste path.
- In-session distribution hook (plugin-hints.md): 'Your CLI writes a one-line marker to stderr when it detects it is running inside Claude Code. Claude Code reads the marker, strips it from the output, and shows the user a one-time install prompt.' The same env-var gate (`CLAUDECODE=1`) can be used by `xerj` itself, without the official marketplace: when `$CLAUDECODE` is set, `xerj --help`, unknown-subcommand errors and the first-run message can print a one-line reminder such as the field-report command — the doc's table ('--help output: Claude often runs help when exploring an unfamiliar CLI') names exactly the touchpoints where an agent is already reading output.
- Heading hygiene lesson (inferred from XERJ, not from Claude Code): Claude Code's index has no 'Optional' section at all; XERJ's field-report link lives under '## Optional' (line 223) while Start-here line 24 says 'File your field report — required'. Rename that section (e.g. '## Your side of the deal') or move the report link into Start here so the heading and the instruction agree.
