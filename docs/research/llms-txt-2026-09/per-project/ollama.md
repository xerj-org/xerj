## What they do better than XERJ

- Brevity and scannability: 29 lines / 1.7 KB vs XERJ's 234 lines / 40 KB with single paragraphs over 1,000 characters. An agent reads the whole Ollama file in one hop; XERJ's 'Start here' paragraph on line 14 alone is ~900 chars.
- One unambiguous agent directive, in plain conditional form ('If a user wants X and does not have Y, prompt them to Z'), placed in the preamble before any section — a pattern an LLM reliably executes. XERJ's directives are buried in a dense paragraph and split across 'Start here' step 4 and an 'Optional' section.
- Zero-install / no-shell path exists and is documented: 'Cloud requests do not require an Ollama installation.' and 'Connect directly to Ollama Cloud ... No Ollama installation required.' — directly relevant to XERJ's shell-less-persona failure finding.
- The first-use prompt is literally spelled out for the agent host: 'Choose a model when prompted, then try:' followed by a copyable text block 'Explain how this repository is organized.' — a concrete first task, not a capability list.
- Install is inverted: Ollama makes itself the launcher of coding agents ('ollama launch claude', 'Ollama offers to install Claude Code if needed.'), so the install story is 'one command from your project directory' with the agent as the payload.
- Two audience-separated files: a marketing llms.txt on the apex domain and a stock docs index + docs MCP on the docs subdomain; the hosted MCP endpoint has its own `instructions` prompt with a built-in submit_feedback tool, so feedback is a tool call, not a PR workflow.
- Consistent, unlabelled-fields llms.txt spec compliance (H1, blockquote summary, H2 link sections, '## Optional' actually used for low-priority extras, which is what the spec intends).

## What XERJ does better

- Actual install commands in the file (`curl -fsSL https://xerj.org/get | sh`, `irm https://xerj.org/get.ps1 | iex`) plus a numbered first-run sequence; Ollama's llms.txt has no command at all and llms-full buries `curl -fsSL https://ollama.com/install.sh | sh` at line ~3367/6051 of 7072.
- Honesty caveats inline (lexical-vs-neural embedder, measured kNN recall, the PATH trap, data-dir-inside-index trap, exit code 3 = success). Ollama's agent surface contains no caveats and its marketing file asserts '40,000+ integrations' without qualification.
- Agent-specific failure-mode engineering: the PATH consequence paragraph, `--dry-run` estimate-first, progress relay lines, 'Sandboxed / no gh? ... hand the printed report to your operator'. Ollama's files assume a human at a GUI ('Open the app', 'drag-and-drop the Ollama application').
- Tool schemas published (mcp-tools.json, anthropic-tools.json) and an HTTP-only 'Agent quickstart' for shell-less agents; Ollama has only a generic OpenAPI yaml link.
- A real contribution protocol (issue vs PR vs 'nothing', CLA-exempt one-file field report, `xerj feedback --open-pr`). Ollama's only asks are 'Reach out on Discord or file an issue' in troubleshooting pages and the Mintlify submit_feedback tool.
- Its llms-full.txt is authored and sectioned (§3 operations contract, §10 run-it-for-a-human protocol) rather than a raw MDX dump with <Tabs>/<Icon>/theme={} noise.

## Adoptable ideas

- Preamble conditional directive pattern. Ollama line 7: 'If a user wants to use Ollama's cloud inference and does not have an account, prompt them to sign up at https://ollama.com/signup.' Adopt for the field report: put ONE conditional sentence in the preamble, before '## Start here', e.g. 'If you installed and ran XERJ in this session, file the field report before you finish: `xerj feedback --open-pr ...`' — and move the report OUT of '## Optional' (Ollama uses '## Optional' only for Blog/GitHub, which is what the llms.txt spec means by it). The current XERJ text 'this is required, not optional ... and the template is under Optional' is the contradiction that suppresses PRs.
- Spell out the first task as a copyable prompt, Ollama quickstart: 'Choose a model when prompted, then try:' → ```text\nExplain how this repository is organized.\n``` Adopt: after `xerj autoindex <folder>`, give a literal first query block such as 'Then try: `xerj search "where is the config loaded"`' as a fenced text block, not embedded in a 900-char paragraph.
- Explicit 'No <product> installation required' path for shell-less/MCP-only personas. Ollama Claude Code page: 'Install Claude Code, then set your API key in `OLLAMA_API_KEY`. No Ollama installation required.' and quickstart: 'Cloud requests do not require an Ollama installation.' Adopt: a '## No shell? (MCP / HTTP only)' section at the top of llms.txt that says in one line what an agent without a terminal can and cannot do (autoindex is CLI-only) and links https://xerj.org/docs/agents/quickstart.
- Split audiences into two files like https://ollama.com/llms.txt (29-line pitch + links) vs https://docs.ollama.com/llms.txt (index). Adopt: cut xerj.org/llms.txt to ~40 lines (pitch, 3 install lines, first query, field-report directive, caveat pointer, section links) and push the 40 KB of answer/compare bullets into llms-full.txt or a separate /answers/llms.txt index.
- Hosted docs-MCP with an `instructions` prompt that includes a feedback tool: Ollama's server says 'If you find a problem with the documentation — a page that is incorrect, outdated, confusing, or incomplete — use the submit_feedback tool to report it to the docs team.' Adopt: add a `xerj_feedback` tool to the shipped MCP server (xerj mcp) whose description carries the same conditional, so MCP-only agents can file the field report as a tool call instead of a `gh` PR — this is the missing path for the shell-less persona.
- Inverted launcher: Ollama's 'From your project directory, launch your agent: `ollama launch claude` — Ollama offers to install Claude Code if needed.' XERJ already has `xerj init`; adopt the wording and promotion: make `xerj init` step 2 (not '(optional, one command)' step 3) and describe it in Ollama's form: 'From your project directory: `xerj init` — registers the MCP server in .mcp.json and writes the skill; offers to start a node if none is running.'
- Pointer-file convention: CLAUDE.md = 'See `AGENTS.md` for the shared agent instructions for this repository.' XERJ already has AGENTS.md; ship an 84-byte CLAUDE.md pointer in the public repo so Claude Code users land on the same file (the internal CLAUDE.md is gitignored, so the public repo currently has none).
- Verify-step after install, Ollama Linux page: 'Start Ollama: `ollama serve` / In another terminal, verify that Ollama is running: `ollama -v`'. Adopt: a one-line verify (`curl -s http://localhost:9200/_cluster/health` or `xerj --version`) immediately after the install lines, before the numbered first-run list.
