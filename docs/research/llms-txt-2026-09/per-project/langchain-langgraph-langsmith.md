### LangSmith Remote MCP quickstart (inside llms-full ~line 61683) — HTTP 200

<https://docs.langchain.com/llms-full.txt>

Per-client MCP config for the LangSmith product server, including the post-install verification step and the tool-name convention an agent will see.

````text
Add the server to your project's `.mcp.json` (or run `claude mcp add --transport http -s user langsmith https://api.smith.langchain.com/mcp` to install it user-wide):

```json
{
  "mcpServers": {
    "langsmith": {
      "type": "http",
      "url": "https://api.smith.langchain.com/mcp"
    }
  }
}
```

Then run `/mcp` and select **langsmith** to complete the OAuth flow. Tools become available as `mcp__langsmith__<tool_name>`.
````

## What they do better than XERJ

- A dedicated, copy-button agent prompt for self-installation that is host-agnostic: 'Detect which agent or editor I am using (Claude Code, Cursor, Codex CLI, Claude Desktop, Deep Agents Code, VS Code, Antigravity, or another MCP-compatible client)' — this is the exact fix for XERJ's shell-less-persona failure: the install path is MCP-config, not a terminal, so a no-terminal agent can still complete it.
- The prompt ends with a guardrail and a verification step: 'Do not invent alternate MCP URLs. After configuring, confirm both servers are listed and reachable.' XERJ's llms.txt has no post-install check step written for the agent.
- Per-client MCP snippets for 7 hosts, each with the client's OWN field names (Cursor 'url', Deep Agents 'type':'http', VS Code top-level 'servers', Antigravity 'serverUrl'), plus scope guidance ('project scope by default; use `--scope user` only if I ask for global access'). XERJ documents only `xerj init` writing `.mcp.json` and mcp-tools.json; no per-host JSON.
- Tells the agent what the tools will be called after install: 'Tools become available as `mcp__langsmith__<tool_name>`.' — reduces first-use fumbling.
- Every standalone .md page carries a 3-line machine preamble pointing back to llms.txt ('Fetch the complete documentation index at: https://docs.langchain.com/llms.txt / Use this file to discover all available pages before exploring further.'), and every page footer repeats 'Connect these docs ... via MCP' and 'file an issue' (565/566 occurrences) — the ask is on every hop, not one section.
- Section indexes carry page counts ('460 pages', '40 pages'), letting an agent budget context before fetching; language corpora are split into separate llms-full files instead of one 7MB blob for everything.
- Skills as an install channel: 'npx skills add langchain-ai/langsmith-skills --skill '*' --yes' with local/global/--agent claude-code variants and an explicit update recipe ('To update, re-run the command. If target skill folders already exist, remove them first').
- AGENTS.md separates 'optional just-in-time context' from 'required startup reading' explicitly and tells the agent what is authoritative ('Treat source code and tests as authoritative') — a clear precedence rule XERJ's llms.txt lacks.

## What XERJ does better

- XERJ's llms.txt is a curated agent guide with the install one-liner on line 11 and a 'Start here' walkthrough; LangChain's root llms.txt is a pure auto-generated Mintlify index with zero install content (install is only reachable one hop away in .md pages, and the MCP prompt sits at ~line 147271 of a 153,516-line llms-full).
- Honesty/caveats inline: XERJ's '## Caveats (read before you rely on a capability)' section (lexical-vs-neural default, --embed-mode applies at ingest, RSS sizing, _passage projection) has no analogue; LangChain's files make no capability caveats at all.
- Verified install: XERJ documents SHA-256 fail-closed checks, a manual verified path, PATH consequences, XERJ_VERSION pinning; LangChain's dcode install is a bare 'curl -LsSf https://langch.in/dcode | bash' with no checksum and no manual path.
- A concrete, one-command contribution mechanism ('xerj feedback --open-pr ... CLA-exempt PR') and a sandboxed fallback ('hand the printed report to your operator'); LangChain's feedback ask is only 'Have questions or feedback? Let us know in our [community forum]' and per-page 'file an issue'.
- Tool schemas published as data (mcp-tools.json, anthropic-tools.json generated from a real tools/list) — LangChain publishes MCP URLs but no tool schema file.
- XERJ's llms-full (84 KB) is readable in one context; LangChain's (6.9 MB, unrendered JSX) is not.
- No stale entries: LangChain still serves python.langchain.com/llms-full.txt as 1 MB of HTML and the LangGraph gh-pages llms-full is 404.

## Adoptable ideas

- Add a host-detecting MCP install prompt block near the top of llms.txt, modelled on https://docs.langchain.com/use-these-docs.md: 'Detect which agent or editor I am using (Claude Code, Cursor, Codex CLI, Claude Desktop, ... or another MCP-compatible client). Use the matching setup from <this page>' — with XERJ's `xerj mcp` stdio server as the target. This directly addresses the shell-less persona failure: give them a path that is config, not shell.
- Copy the closing guardrail + verification line verbatim in spirit: 'Do not invent alternate MCP URLs. After configuring, confirm both servers are listed and reachable.' → for XERJ: 'Do not invent alternate ports or index names. After configuring, run tools/list (or `/mcp`) and confirm xerj_search is listed, then run one search and cite the file:line it returned.'
- Publish per-client MCP JSON with each client's own field names, as use-these-docs.md does (Claude Code `claude mcp add --transport ...`, Cursor `{"mcpServers":{"x":{"url":...}}}`, VS Code `{"servers":{...}}`, Antigravity `serverUrl`, Codex `codex mcp add`), and state the resulting tool names as LangSmith does: 'Tools become available as `mcp__langsmith__<tool_name>`.' → 'Tools become available as `mcp__xerj__xerj_search` ...'.
- Adopt the scope sentence verbatim pattern: 'project scope by default; use `--scope user` only if I ask for global access' — XERJ's `xerj init` should say which scope it writes and how to make it global.
- Put the ask in every hop, not one section: LangChain repeats 'Connect these docs ... via MCP' and 'file an issue' in a footer on all 565 pages, and every standalone .md starts with '> ## Documentation Index / Fetch the complete documentation index at: https://docs.langchain.com/llms.txt'. If target skill folders already exist, remove them first' — XERJ's `xerj init` 10-line skill could also be published to a xerj-org/xerj-skills repo installable that way, reaching agents that never run the binary.
