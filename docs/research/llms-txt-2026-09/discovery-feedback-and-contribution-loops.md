# Discovery notes — feedback-and-contribution-loops

Angle, as the agent labelled its own run: Feedback and contribution loops: how developer projects get reports, issues and PRs FROM AI agents and their users at scale — agent-facing "report back" instructions in llms.txt/AGENTS.md, CLI feedback/bug subcommands, agent-aware issue/PR templates and disclosure conventions, CLA-exempt or gated contribution paths, telemetry-with-consent wording, Discord/Discussions funnels, and the volume evidence behind each. Method: curl -sL of ~150 llms.txt (status+final URL recorded; 404s listed inline), ~80 raw AGENTS.md/CONTRIBUTING/template files, GitHub code search (filename:AGENTS.md / llms.txt / PULL_REQUEST_TEMPLATE.md) and GitHub issue search counts. CAVEAT on counts: GitHub search is token-based, not exact-phrase, so quoted-phrase totals are upper bounds (e.g. '"Generated with Claude Code" is:pr' returns 11,969,526 and '"Generated-by:" is:pr' 38,562,778 — both clearly inflated); narrow multi-word sentences are more trustworthy.

Each note is one agent's observation with the URL it fetched on 2026-09-18, recorded verbatim. INFER / INFERENCE markers are the agent's own.

## Patterns observed

1. AGENT-DRAFTED FEEDBACK (event-triggered, human-approved): Claude Code SendFeedback — https://code.claude.com/docs/en/tools-reference.md — 'Claude drafts one with the SendFeedback tool when: * A tool or command keeps failing * It can't help with something you asked for * You point out a mistake it made, or it notices one * You ask it to file feedback' ... 'Press `1` to review the draft, press `2` twice to send it as written, or press `0` to dismiss it.' — trigger is the failure, not the session end; consent is a keystroke.

2. CLI FEEDBACK SUBCOMMAND THAT SUBMITS DIAGNOSTICS (no GitHub, no CLA): Codex — https://learn.chatgpt.com/docs/developer-commands.md?surface=cli — '### Send feedback with `/feedback` 1. Type `/feedback` and press Enter. 2. Follow the prompts to include logs or diagnostics. Expected: Codex collects the requested diagnostics and submits them to the maintainers.'; Amp — https://ampcode.com/docs/markdown/support/reporting-bugs — 'amp report-bug "describe the bug"' ... '`amp report` and `amp diagnostics` are aliases for `amp report-bug`.' ... 'Diagnostic data is deleted after 7 days.'

3. CLI /bug THAT PRE-FILES A GITHUB ISSUE: Gemini CLI — https://geminicli.com/docs/reference/commands.md — '### `/bug` - **Description:** File an issue about Gemini CLI. By default, the issue is filed within the GitHub repository for Gemini CLI. The string you enter after `/bug` will become the headline for the bug being filed. The default `/bug` behavior can be modified using the `advanced.bugCommand` setting'; Claude Code /bug shares the /feedback path — https://code.claude.com/docs/en/data-usage.md — 'Transcripts shared via `/feedback`, or via `/bug` and `/share`, which report through the same path, are retained for 5 years.'

4. PURE-HTTP AGENT FEEDBACK ENDPOINT (works without a shell): Expo — https://docs.expo.dev/agents.md — 'Direct HTTP fallback: curl -X POST https://api.expo.dev/v2/feedback/docs-send -H 'Content-Type: application/json' -d '{"url":"/agents/","feedback":"🤖 Agent feedback for docs: <specific, actionable description> (<model>, <harness>)"}' Only submit when you have something specific and actionable to report.' — the payload itself asks for model + harness, which is the field-report metadata XERJ wants.

5. MANDATORY AGENT FEEDBACK COMMAND IN AGENTS.md, WITH SANDBOX NO-OP: PostHog — https://raw.githubusercontent.com/PostHog/posthog/master/AGENTS.md — '`hogli devex:feedback "<message>"` sends feedback about repo tooling ... (add `-c bug|idea|praise|question`). **Local agents must use it too**: when a hogli command or local dev workflow is broken, slow, or confusing, run it ... Do not run it from cloud tasks or agent-server sandboxes; the command is a no-op there.'

6. 'TELL US WHAT YOU CAME FOR' ONE-LINE ASK WITH VISIBLE VALUE + SLA: Vexa llms.txt — https://raw.githubusercontent.com/Vexa-ai/vexa/dba990b413bd0f888b02d46a24f802db492addbb/docs/docs/llms.txt — 'We can see that these pages get fetched; we cannot see the question. If you tell us, the next reader gets a page that answers it — that is the whole loop, and you are the only one who can close it.' ... 'say, in one line, **what you were trying to do** — not only what was missing.' ... 'A human reads every one.' ... 'three days is our target'.

7. 'OPEN AN ISSUE, NOT A PR' + DISCLOSE + NO FIX SNIPPETS: OpenTofu AGENTS.md — https://raw.githubusercontent.com/opentofu/opentofu/main/AGENTS.md — 'If you or a human you are assisting has identified a problem with the help of an LLM then you must **open an issue to discuss** and you **MUST NOT open a pull request**. It is **strictly prohibited to include code snippets** for possible fixes.'

8. INFERENCE (not stated by any source): every project that receives agent contributions at volume either (a) pulls them by assigning/labelling issues (Copilot, Jules, Cursor automations, ai-manus 'agent-task' template) or (b) ships a zero-CLA, zero-git channel inside the tool (Claude Code SendFeedback, Codex /feedback, Amp report-bug, Expo HTTP POST, PostHog hogli). No project other than XERJ asks agents in llms.txt to open a PR as an obligation, and the repo-side AGENTS.md rules agents actually operate under (Sonarr, ModernUO, FreeToken, Next.js, LLVM, Zed) generally forbid an agent from opening a PR/issue without the human approving the exact draft — so 'required' in llms.txt is overridden by the agent's own repo rules and the operator's permission prompt, which is consistent with the 22-run study's low report rate.
