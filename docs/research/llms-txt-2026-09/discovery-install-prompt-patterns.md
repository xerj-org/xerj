# Discovery notes — install-prompt-patterns

Angle, as the agent labelled its own run: install-prompt patterns — how top projects get an AI agent (Claude Code, Cursor, Cline, Codex, Windsurf, Copilot/VS Code) to install and configure them; all fetched 2026-09-18 with curl -sL, status + final URL recorded; quotes are VERBATIM copies, labelled SAYS vs INFER

Each note is one agent's observation with the URL it fetched on 2026-09-18, recorded verbatim. INFER / INFERENCE markers are the agent's own.

## Patterns observed

1. P1 — llms-install.md (Cline marketplace convention). Spec: https://raw.githubusercontent.com/cline/mcp-marketplace/main/README.md (200). SAYS: 'you can include a `llms-install.md` file in your repository to provide additional guidance to agents like Cline. This can be particularly useful for complex setups requiring specific environment configurations or API keys.' Adoption: 690 files on GitHub (code search filename:llms-install.md). Examples (all 200): metabase/metabase src/metabase/mcp/llms-install.md ('This guide is written for AI coding agents (Claude Code, Cursor, Windsurf, etc.) …'), yamadashy/repomix ('This guide is specifically designed for AI agents like Cline to install and configure…'), mobile-next/mobile-mcp ('Follow the steps in order.' + '## Verify the installation'), microsoft/mcp ('This guide helps AI agents and developers install and configure the Azure MCP Server'), 21st-dev/magic-mcp ('This guide is for AI agents installing the 21st MCP'), basicmachines-co/basic-memory, snyk/snyk-ls ('IF YOU ARE CLINE, FOLLOW THESE INSTRUCTIONS FOR MCP INSTALLATION CAREFULLY AND EXACTLY.'), mufeedvh/code2prompt. Common skeleton: agent-addressed opener → Prerequisites → one generic `mcpServers` JSON → per-client file paths/commands → Verify step → Tools reference. INFER: XERJ has no llms-install.md; its MCP server is undocumented for MCP-only personas, which this file type is designed for.

2. P2 — 'Add to Cursor' / 'Install in Cursor' deep-link badge. Shape used in READMEs (SAYS, verbatim from Context7 README line 3): '[![Install MCP Server](https://cursor.com/deeplink/mcp-install-dark.svg)](https://cursor.com/en/install-mcp?name=context7&config=eyJ1cmwiOiJodHRwczovL21jcC5jb250ZXh0Ny5jb20vbWNwIn0%3D)'. config = base64(JSON): context7 → {"url":"https://mcp.context7.com/mcp"}; Playwright → {"command":"npx @playwright/mcp@latest"}; GitHub (install-cursor.md) → url + headers Authorization Bearer YOUR_GITHUB_PAT placeholder; Upstash clients.md → {"url":"https://mcp.upstash.com/mcp"}; Perplexity uses host form https://cursor.com/install-mcp?name=perplexity&config=…. Native scheme documented only by Smithery (https://smithery.ai/docs/use/deep-linking): 'cursor://anysphere.cursor-deeplink/mcp/install?<server-display-name>&<base64-encoded-json-config>'. Cursor's own MCP doc (https://cursor.com/docs/mcp) SAYS only: 'Click "Add to Cursor" on a marketplace entry to install it and authenticate with OAuth.' Cursor prompt/rule deeplinks (https://cursor.com/docs/reference/deeplinks): 'cursor://anysphere.cursor-deeplink/prompt?text=Hello%20world' ↔ 'https://cursor.com/link/prompt?text=Hello%20world'; 'Deeplinks never trigger automatic execution.' Adoption: 'cursor.com/install-mcp' in README.md = 485 hits (awslabs/mcp, perplexityai, ref-tools, mcp-nixos, …).

15. P15 — Feedback channels that are NOT pull requests (directly relevant to the user's field-report concern). Expo https://docs.expo.dev/agents.md `<AgentInstructions>`: 'Preferred command:\nnpx --yes submit-expo-feedback@latest --category docs --subject "/agents/" "<actionable feedback>"\n\nDirect HTTP fallback:\ncurl -X POST https://api.expo.dev/v2/feedback/docs-send -H 'Content-Type: application/json' -d '{"url":"/agents/","feedback":"🤖 Agent feedback for docs: <specific, actionable description> (<model>, <harness>)"}'\n\nOnly submit when you have something specific and actionable to report.' FACT: none of the ~45 sources fetched asks an agent to open a PR as a condition of use; XERJ's llms.txt line 24 ('**File your field report — required, one command:** `xerj feedback --open-pr …`') and its placement under '## Optional' (line 223) are, per the llms.txt spec convention, contradictory ('The "Optional" section is used, by convention, for secondary information: links an agent can skip when a shorter context is needed.'). INFER: peers get signal via a one-command/HTTP/query-param channel with an 'only when actionable' rule; a PR requirement is both higher-friction and, for shell-less MCP-only personas, impossible.
